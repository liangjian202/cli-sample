## AgentToolsDemo：两种方式实现同一组文件工具（.NET）

- 位置：`AgentToolsDemo/`（.NET 9 控制台，Microsoft.Agents.AI 1.27.0 + Microsoft.Agents.AI.OpenAI）
- 目的：演示「CLI 对 agent 而言只是另一个工具」，同一份入参 schema 分别用托管 API 与 PowerShell 实现 create/delete file & folder
- 文件：`FileOpContract.cs`（共享 schema）、`CodeFileTools.cs`（System.IO）、`CliFileTools.cs`（powershell.exe + 环境变量传数据）、`Sandbox.cs`（路径越界拦截）、`Program.cs`（三轮回放 + 可选接真实模型）
- 踩到的坑：PS 5.1 `Set-Content -Encoding utf8` 写 BOM，导致生成文件比 API 多 3 字节；改用 `UTF8Encoding($false)` + `WriteAllText`
- 结论：结构化 function calling 下，工具选择与是否 CLI 无关；安全边界只能放在运行时

## 补充：第三层 L3 `run_command`

- 新增 `ShellTool.cs`：命令字符串由模型生成，运行时做「算子黑名单 + 高危指令正则 + 路径归属校验」后再执行
- 三层划分：L1 纯 API（code_file_ops）/ L2 固定命令模板（cli_file_ops）/ L3 通用命令执行（run_command）
- 坑：PS 5.1 控制台输出默认 OEM 代码页，中文乱码；在 `-Command` 前置 `[Console]::OutputEncoding=[Text.Encoding]::UTF8` 解决
- 提醒：demo 级的正则守卫不等于沙箱，生产需要容器隔离 + 审批环节
- 用 .NET 9 控制台应用实现 FileCli（filecli）：file/dir 的 create/delete 四个命令，AI-Friendly 设计（JSON 输出 --format json、--dry-run、退出码 0/1/2、stdout/stderr 分离、从不交互等待），csproj 配置 PackAsTool 可打包为 dotnet global tool。skills/ 下为每个功能生成独立 SKILL.md（file-create/file-delete/dir-create/dir-delete），删除类 Skill 强调先 dry-run 再向用户确认。构建实测全部通过。
- 讨论结论：Skill 是知识不是能力，Agent 必须有 shell 执行 tool 才能用；无 shell 宿主需 MCP（官方 C# SDK：ModelContextProtocol NuGet 包）。
